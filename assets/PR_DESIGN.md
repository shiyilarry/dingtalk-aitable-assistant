# PR_DESIGN.md — 方案设计类报告渲染规范（锁定版 v1.0 · 案例视觉）

> **锁定记录**：2026-09-05 视觉评估二次锁定。方案设计类 HTML 一律采用「案例视觉」（母本：《案例_钉钉AI表格实现方案.html》的 UI 语言 + 本 SKILL 内容结构要求）。
> 经实机对比，本风格（渐变 Hero、4 色语义、白卡、斑马纹表）比纯白官网风在全量长文档下更直观易读。
> 审计类仍用 `AR_DESIGN.md`（Resend，深色终端级），二者不可混用。

**Theme:** light · 办公文档亲和风 · 系统字体零外链依赖（离线观感一致）

## 设计语言一句话

浅灰画布上的白色内容卡 + 深青绿→蓝「渐变横幅 Hero」+ **蓝/绿/橙/紫 4 色语义系统**（tag、callout、表格表头、分层图卡）贯穿全文；小节标题左侧 4px 绿竖条；数据表格绿头 + 斑马纹；关键图一律 SVG 分层图 + 图题。

## 内容结构（方案类全量颗粒度，缺一不合格）

1. 文档头（类型/版本/状态/日期）→ 2. 方案总览与结论（核心机制一句话 + 高亮块 + 关键结论清单）→ 3. 需求拆解与设计观（含隐含场景主动补全表）→ 4. 总体架构（**先放 SVG 分层图**，再域/表分布）→ 5. 表间关系设计（关联/查找引用/选项同步 + 文本键口径声明）→ 6. 逐表规格（每表：职责 + 全字段表 字段名/类型/选项说明 + 关联行 + 口径高亮块）→ 7. 统计列与关键公式（filterUp 配置参考 + 公式代码块带复制）→ 8. 自动化流转（触发条件→动作 步骤化轨道）→ 9. CLI 能力矩阵（实测标注 CLI 支持/受限 + UI 指引）→ 10. 示例数据与验收（业务链顺链核验）→ 11. 交付清单与下一步。

## Do's

- Hero 一律渐变横幅 + meta 徽章；正文段落杜绝「大片纯白无视觉锚点」——每个口径提示/结论都给语义色高亮块。
- 语义色固定：核心机制/成功=绿、警示=橙、危险=红、配置/主档=蓝、结果/统计=紫；tag 与分层图卡同色系呼应。
- 所有跨表统计/聚合在架构图与公式中明确「由谁算」：查找引用 filterUp 自动 or 公式 or 自动化。
- 所有公式给出可复制代码块；需要人工参照搭建的流程给步骤化（steps/节点轨道）呈现。
- 分层图按「配置→底表→中间/账本→结果」纵向分层表达数据流，卡上注明行规模/关键机制。

## Don'ts

- 不要用大段黑字白底的普通段落承载「重点提示」——用语义 callout。
- 不要贴 HTML/代码标签原文（如 `<code>` 字面）——富文本必须经渲染层生成。
- 不要用深色块/霓虹渐变（那是审计 AR 的语言）；方案文档保持浅色亲和。
- 不要把分层图简化为文字列表；多表/多层方案必须给 SVG 分层图。
- 不要在正式版里残留「视觉测试/样例节选」措辞与旧版评审过程说明。

## 渲染执行备注

- 一键复制按钮 JS：`navigator.clipboard.writeText(pre.innerText)` + 「已复制 ✓」反馈。
- 滚动渐显：IntersectionObserver + .reveal（克制，500ms）。
- 锚点：主节 `<section id="s01..">` + toc。
- 适用：场景一搭建方案（评审稿/正式）、场景二同步报告（表格统计，可用其简化版）、SKILL 方案类交付物。
