# 钉钉AI表格助手（dingtalk-aitable-assistant）

> 面向**非 IT 同事**的钉钉 AI 表格自动化助手：用大白话说需求，完成「**建表 / 数据同步 / 表格审计**」三件事与看板搭建——全流程自动执行，无需写代码。

## 它解决什么问题（三大场景）

本技能的现有能力，是**基于真实办公工作场景**设计、并**经过多个真实项目长期验证迭代**出来的：

| 场景 | 典型需求 | 技能做什么 |
|---|---|---|
| **① 搭建** | 「帮我建一个客户管理表 / 按月做一张经营分析表」 | 从一句话需求出发：设计表结构 → 建库建表建字段（含关联/查找引用）→ 出设计方案档案 |
| **② 同步** | 「把本地 Excel / 计算结果同步到线上表（含增量/覆盖/补列）」 | 读本地数据 → 线上结构对齐 → 校验清洗 → 写前预览 → 分批复写入 → 同步报告（幂等可重跑） |
| **③ 审计** | 「看看这个表有没有问题 / 对照需求评估一下」 | 只读体检（结构/口径/容量/性能）→ 分级结论与优化建议 → 审计报告 |

## 工作原理

技能内部按「**六段式执行流程**」工作，并全程自带护栏：

**P0 环境前置**（自动装好/升级 `dws`、引导登录，你无需操作）→ **P1 意图路由**（判断属于哪个场景）→ **P2 场景执行**（按对应 Playbook 逐段推进）→ **P3 交付物**（报告/档案，见下）→ **P4 交付前自检**（结构/数据/展示三层核验，**由技能自己完成，不把校验责任推给你**）→ **P5 复盘进化**（实战经验沉淀为经验卡）。

三大场景各自的完整工作过程：

### 场景一 · 搭建：需求 → 方案 → 确认 → 开工 → 验收交付

整个生命周期在**同一份《项目设计方案》档案**里演进（可追溯、不散落）：

1. **接收需求**——技能先问清业务背景、核心字段、谁填谁看、表格版本；一句话模糊需求会先给 2~3 个澄清问题；
2. **方案产出**——产出一份《设计方案》档案（HTML）：需求拆解、总体架构图、数据表设计（含关联/查找引用）、口径规范、合规自查……**此时一张表都不会建**；
3. **评估确认**——你和业务方评审，意见在档案「评审与决策记录」中逐轮更新；可多轮修订，直到你明确"**确认最终版**"；
4. **正式开工**——确认后才开始建库、建表、建字段、导入数据；需要看板/视图的一并搭建（含布局归一化）；
5. **验收交付**——技能先跑交付前自检，再把「示例数据与验收交付」追加进同一档案，状态徽章转为「**已交付**」。

> 铁律：**先方案后开工**——未经确认不建任何表；确认后的实现不得静默缩水（有变动先说明）。

### 场景二 · 同步：读数据 → 对齐 → 校验 → 预览 → 写入 → 报告

1. **读本地数据**（Excel/CSV/粘贴文本）并**对齐线上表结构**（缺列会先问你，不擅自改表）；
2. **校验清洗**：必填、类型、日期格式、去重键唯一性；
3. **写前预览（关键闸门）**：先给出「将新增 N / 更新 M / 跳过 K」的统计与抽样对比，**你确认后才真正写入**；
4. **分批复写入**：按 100 条/批自动分批，失败可断点重跑（**重跑不会写重复**）；大批量支持幂等键与基线复核；
5. **同步报告 + 复核**：写入后回读逐项核对，出一份简洁的同步报告（成功/失败/明细可导出）。

### 场景三 · 审计：只读体检 → 多源对照 → 分级结论 → 审计报告

1. **只读扫描**：表结构、字段、视图、样例数据（**全程不修改任何表/字段/数据**）；
2. **多源对照**：结合你的需求材料（文档 / Excel / 会议记录）做符合度矩阵；
3. **分级结论**：按「阻断级 / 重要 / 一般」逐条列问题 + 修改建议（区分"技能可直接执行"与"需界面操作"）；
4. **审计报告**：评级总览置顶，附最小改动路径；如需落地优化，可转场景一/二继续（仍先确认）。

---

**真实项目验证范围**（脱敏表述）：财务数据协同与对账、多平台数据源对等监测、电商渠道商品分析、资金账单补数与执行凭证核对、跨系统数据同步等——覆盖多种真实业务场景，并在长期使用中持续沉淀平台经验与口径纪律。

## 适用环境与依赖

- **操作系统**：Windows 10/11
- **宿主**：[WorkBuddy](https://www.workbuddy.cn/)（本技能按 WorkBuddy Skill 规范打包）
- **依赖**：Node.js ＋ 钉钉官方 `dws` CLI（首次使用由技能自动引导安装／升级）
- **账号**：钉钉账号（自动引导登录授权）

## 安装

1. 将本目录 `dingtalk-aitable-assistant` 复制到 `%USERPROFILE%\.workbuddy\skills\` 下；
2. 重启 WorkBuddy；
3. 首次使用时技能会自动检查并引导安装 `dws`，请保持网络畅通。

## 快速上手（三大场景各一个示例）

**场景一 · 搭建**

> 🗣️ 你：「帮我做一张按月的经营分析表，要能按店铺看利润和销量」
>
> ⚙️ 技能：先问清字段与口径 → 产出《设计方案》档案（架构图 + 表设计 + 口径）→ 你确认"最终版" → 建库建表建字段、导入示例数据

> 🗣️ 你：「把当前文件夹的销售数据.xlsx 同步到我的项目进度表」

## 安全与边界（诚实声明）

- **零破坏**：未经确认不修改任何现有表 / 字段 / 数据；删除类操作一律先快照备份。
- **敏感脱敏**：输出与报告中不出现真实项目名 / ID / 财务明细 / 品牌名（示例一律「示例××」）。
- **能力边界**：一切能力以运行时实测为准（`dws schema`）；做不到的会**明说**，不硬凑。
- **非官方技能**：本技能为社区作品，与钉钉官方无隶属关系；使用需遵守钉钉平台相关条款。

## 常见问题

**Q：提示“dws 不是可识别的命令”？**
A：技能会自动安装；如失败可手动执行 `npm install -g dingtalk-workspace-cli`。

**Q：登录失败 / 截图授权失效怎么办？**
A：执行 `dws auth login` 手动登录，或检查网络代理；看板截图所用登录态过期时，技能会提示重新授权（一次扫码，长期复用）。

**Q：数据量大时同步慢？**
A：同步按 100 条/批自动分批并支持断点重跑；大批量建议保持网络稳定、避开高峰时段。
