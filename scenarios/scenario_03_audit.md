# 场景三：表格审计与优化建议（Playbook · 只读）

## 触发
"看看/分析一下这个表 / 对照需求评估 / 帮我找问题" / 对既有 AI 表格做实现方案与需求的符合度审计

## 铁律
**只读审计**：可读结构、字段、视图、配置、样例数据及本地依据文件（Excel/md/pdf/音频转写），**不修改任何表/字段/条件/配置**，也不改动用户提供的本地依据文件。

## 子阶段
### S1 读表格结构（线上侧，只读）
- `table list` 定位；对每个相关表 `field list`（名称/类型/config，注意公式类字段的既有逻辑可作为需求佐证）；记录视图名（可反映已建筛选）。
- `record list --limit N` 取样例，观察字段填充与数据质量（不拉全量，除非用户要求规模评估）。

### S2 读需求来源（多源综合，不能只靠单一纪要）
按可得性依次收集并**综合**为审计依据：
1. 用户口述/文字需求；语音或会议**音频/转写**（注意：AI 转写可能省略细节或错漏，仅作线索，需其它来源交叉验证）；
2. 会议纪要 / 需求文档（pdf→文本提取 / md / 其它格式只读提取）；
3. **Excel 需求表/模板/实际业务表**：读取表头、数据样例与**表内既有公式逻辑**（openpyxl 等本地只读提取，不改文件）；这类事实型来源优先级最高；
4. 其它（原型/截图/口头补充要点）。
- 读不到/不足时请用户粘贴要点或补材料；无任何需求时降级为「通用最佳实践」审计并在报告说明口径。
- 产出：报告「需求与依据」节的**符合度矩阵**（需求条目 × 依据来源 × 现状承接）。

### S3 多维对比
| 维度 | 检查点 |
|---|---|
| 覆盖度 | 需求关键对象/流程是否有表与字段承接（含多源需求里 Excel 表/公式逻辑体现的口径） |
| 类型与键 | 主键/关联键类型、单号是否文本、日期是否日期、比率字段口径、表间是否真关联 |
| 结构与命名 | 是否宽表堆列（年月/店铺作列）、命名统一、选项单一来源 |
| 逻辑口径 | 计算/汇总逻辑是否与需求（含 Excel 公式逻辑）一致、空键隐患 |
| 数据质量 | 样例空值、重复、异常标记（如验算状态=异常） |
| 能力边界 | 需求依赖但平台/CLI 未实现的（公式字段创建/按钮/自动化/OCR/选项同步）逐项列出（**视图/仪表盘/图表已 CLI 支持，不再列**） |

### S4 审计报告（HTML · Resend 风格 · 评级总览置顶）
渲染与结构遵守 `references/report_style_guide.md` §3/§5：
1. **评级总览**（第一部分，置顶）：综合评分（如 8.0/10）+ 总体结论一段 + 关键计数（阻断级×n / 重要×n / 一般×n）；
2. 范围与方法：只读声明 + 审计对象表清单 + 方法说明；
3. 需求与依据：多源依据清单 + 符合度矩阵；
4. 覆盖核验：逐条需求 通过/部分通过/未通过 + 证据；
5. 问题清单：级别（阻断级/重要/一般）/ 现状 / 影响 / 建议（区分 CLI 可执行与需 UI）/ **关闭条件**；
6. 建议执行顺序（阻断→重要→一般 的最小改动路径）；
7. **（可选）项目优化建议**：仅当评估出比现状更优的实现方式时才加，没有则整节不出现；
8. 附录（表结构概览）。
- 措辞纪律：问题级别与符合度用常规中文（见 guide §5）；无重大问题→良好评级+前瞻建议；问题多→按优先级给最小改动路径。

### S5 跟进
- 用户可就建议提问；如需落地优化，转入场景一/二（先确认，仍遵守零破坏）；同一项目二次审计 = 同文件追加带日期审计节。

## 🔴 交付前自检清单
- [ ] 全程只读，未发生任何写操作（含未改动本地依据文件）；
- [ ] 需求依据多源综合（≥2 类可得来源交叉），非单一纪要；
- [ ] 评级总览为第一部分；措辞为常规中文（阻断/重要/一般、通过/部分通过/未通过）；
- [ ] 每个问题有依据（字段/样例/依据原文）；建议区分 CLI 可执行与需 UI；
- [ ] 报告脱敏、无内部措辞残留。
