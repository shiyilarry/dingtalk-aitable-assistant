# 场景二：本地计算 → 数据同步（Playbook · 三模式）

## 触发
"把本地 Excel/CSV/结果同步到 XX 表 / 上传 / 刷新 / 更新某月数据"

## 子阶段
### S1 读本地数据
- 源：xlsx/csv/json/粘贴文本。读取并解析（openpyxl 等本地只读），识别表头、数据起止行、数值/文本原样。
- 单号/编码列强制文本；多级表头（前几行合并标题）→ 仅用首行有效表头。

### S2 线上结构对齐
- `base list`/`table list` 定位目标表；`field list` 取字段与 fieldId。
- 字段差异：线上有本地无 → 留空记日志；本地有线上无 → 询问确认后 `field create`（差异列创建）；类型不符 → 转换/降级 text。

### S3 校验清洗
- 必填、类型、日期格式、去重键（组合键唯一性）。

### S4 模式选择 + 写前预览（关键闸门）
与用户确认「这批数据性质」：
| 模式 | 规则 |
|---|---|
| M1 增量新增 | key 不在→新增；key 在→跳过 |
| M2 叠加更新（默认，计算结果刷新） | key 不在→新增；key 在→按更新范围改写；**历史刷新+全新增可并存** |
| M3 全量重导 | 显式确认→快照→分批清空(--yes)→写入→报告标记 |

M2 内问一次更新范围：整行覆盖 / **仅指定列更新(推荐，保留人工列)** / 跳过已有。
**写前预览**：dry-run 统计「将新增 N / 更新 M / 跳过 K」，M>0 展示 2 行抽样 diff，用户确认后才写。
**差异集写前一刻现算（增量同步，2026-09-23 采纳 EV-202609-24）**：待更新/缺口集必须在**写前一刻**从库内实况重算（含目标窗口内新发生的入库），不得沿用更早时点的清单——"同步后的静止状态"不成立；预览与写入的间隔尽量最短，口径与现算时间写进报告。
**「基线 0 行」对照纪律（2026-10-01 采纳 EV-202609-47）**：按域过滤拉基线得 0 行时**不得直接进入 create**——先跑对照查询（同一过滤结构、换一个已知必有数据的值）：对照组命中 ⇒ 0 行可信；对照组也 0 行 ⇒ 过滤器 / 字段 id 有问题，禁止写入。对照结果（对照组命中数 / 本次基线数）记入预览输出。
唯一键必须用户指认（单号 / 年月+店铺+SKU 组合）；无键禁 M2。
**键选择纪律（2026-09-23 采纳 EV-202609-29）**：定键前先**实测候选键唯一性**（两侧各查重复）；**编码类字段不得默认作键**（实测同一业务实体可挂多编码 → 差集与同步产出成对伪差异）；名称类字段可能改名/重名 → 用「名称+编码」双列并记录取舍判据。
**键粒度纪律（2026-10-01 采纳 EV-202609-43 / 44 · 通用化提炼）**：定键两步——**先测行粒度、再测唯一性**：① 列出「同主体同日可能多行」的维度（分**类别 / 库表 / 指标位 / 来源**…），**凡有多行可能的，键必须含该节点维度**（否则两行互相覆盖或互判「已存在」）；② 多域共用表中该维度同时是**域标记**——本域读取（写前查重 / 回读 / 基线）一律按此列**域过滤**，且**过滤列与键的节点列必须同一**（读 / 写 / 验三通道一致）；③ 单域场景建议**不省略**（换域隔离与脚本族同构）。节点列因表而异，按表结构实测确认、不照搬字段名。

### S5 执行写入
- ≤100/批（--records-file）；失败记录不中断。
- **重试按幂等性分档（2026-09-24 采纳 EV-202609-27）**：幂等写入（update / 带 recordId / `record upsert`·`upsert-by-key`）可重试 ≤3 次；**create 类非幂等写入禁自动重试**（超时 ≠ 未执行，请求可能已落盘）→ 兜底＝重拉基线 → 按键分层（已存在走 update）→ 重跑。
- **批量失败粒度＝批**：单条被拒（参数类）会整批全丢 → **二分到最小单元**定位坏行（好行照写、坏行记失败明细）；网络 / 系统类整批记失败、不二分。
- **新增幂等键（2026-10-01 采纳 EV-202609-45；批边界 2026-10-16 采纳 EV-202610-02）**：多批新增用 `--client-token` 做幂等——**每批一个独立 UUID v4**（禁派生拼接）并**落盘复用**（超时重跑取同批同 token，不重复建行）。**「批」＝同一组记录内容的单次写入**——同内容重跑复用同 token ✓；**新内容（新月 / 新记录集）必须换新 token**：复用旧 token 提交新内容会被 `DUPLICATE_CLIENT_TOKEN` 拒绝（实测 0 落差、直接换新 token 重试即可）；token 落盘文件**按批 / 按内容命名**（勿用全局单文件；可用内容 sha256 前 12 位命名——内容不变自动复用、变则自动换新）。

### S6 同步报告 + P5 复盘
- 报告（简洁表格 HTML）：总/成功/失败/新增/更新/跳过、模式标记、差异列创建清单、失败明细可导出。

## 派生子场景（用户同期要求）
- 主表同步后同步其「-看板」子表：对每个父表 key 相同的子表重复 M1/M2 逻辑（先确认子表口径）。
- **联动对象三查（2026-10-15 采纳 EV-202610-06 · KK 实战）**：① **结果表刷新**——以主表为口径的**结果表**（快照 / 汇总类，供看板取数）须随同步**刷新**（否则看板按其口径显示旧值）；② **字典缺口检查**——新出现的分类值（细类 / 类别 / 库表名…）须核对映射字典完整性，缺失即补（否则联动列（查找引用）为空）；③ **消失行处理**——优先**逻辑删除**（状态列 + 视图 / 看板过滤）保留历史；确需物理删除时**先评估引用面**（自动化 / 表间字段引用 / 看板口径）并备份，再执行。
- 仪表盘补图表/模块（**CLI 实测支持**）：dashboard/chart 流程见 scenario_01 S4.5 与 dws_command_ref 实操纪要（create-only 红线：避免同盘反复 update/delete，大改整盘重建）。

## 写入取值口径与空值纪律（多源协同表 · 2026-09-23 定稿；单源表无此约束）

- **0 ≠ 未知**：有空值语义的列，写入前先确认下游公式/消费者的空值语义；**"未知"不得冒充 0**（实测：平台公式中空白参与数值比较按 0 处理，写错会被下游判成确定值）。
- **平台侧条数纪律**（"平台条数"这类列专有）：
  1. 一律取「导出表格内条数 或 平台页面看到的条数」——**禁止以库内条数替代**（库内兜底属特批例外，不得演变为常态）；
  2. 平台端确认无账单 → **记 0**（不留空）；
  3. **验收目标＝同步后「平台条数 + 库内条数」两列均不为空**；"未采回"只是**补采过渡期的中间态（尽量短）**，该格按缺口继续补采，直至"采到"或"平台确认无"。
- **验收两层纪律（2026-10-15 采纳 EV-202610-03）**：验收＝① 写入命中（回读逐格）＋ ② **口径独立判定**（逐格核对取数来源与约定一致）。实例：397 格回读全绿但 131 格「=0」实为「未拿件（未知）」误写（违反 0≠未知）——**回读只证「写进去了」，不校验值口径**。

## 单选传值排查次序（2026-10-01 采纳 EV-202609-42 · 所有表适用）

写 singleSelect 报 `SELECT_OPTION_NOT_FOUND` 时按序排查：① `field get` 对 option id **逐字符**复核（转抄漏一字符是肉眼盲区）；② 核该选项是否属于当前字段；③ **最后**才怀疑传值形态（`{"id"}` / `{"id","name"}` / 选项名多形态均可用）。**「形态不支持」类结论必须先用零污染实验（对已存在行做 no-op update）证伪**才能下。书写取值优先「选项名字符串」（依赖选项名唯一；有同名 / 近名风险时用 id 形态）。

## 多源协同表：职责边界与报告输出禁令（2026-09-23 采纳 EV-202609-23）

- **只写本侧列**：对位列（由对位项目/系统维护）**不写不判**；本侧验收判据＝本侧列写入正确（回读命中）＋ 本方空白格归零；**对位列空/差异 ≠ 本侧失败**。
- 🟥 **输出禁令**：同步报告/消息中**不得解释、归因、担忧、核查对位列**——「差异」是监测表的正常产出、非异常，无需解释。
- ⚠️ 落地形态必须是**禁令句**（不得写成"职责说明"）：须同时覆盖**报告输出规范与生成脚本的模板字符串**，否则每轮生成时会复发。
- 例外：仅当用户显式要求本侧负责对位列时（需再次确认）。
